## F1 — `controller_id` canónico (🔴)

### Investigación

Verificado en código real (subagente 2026-05-10):
- **No existe un identificador único cross-bot stable** provisto por el backend.
- El servidor del API inyecta `_config_name` (filename del YAML sin extensión) en los configs (`hummingbot-api/routers/controllers.py:303`).
- `update_bot_controller_config(bot_name, config_name, ...)` espera el filename como `config_name`.
- En `get_active_bots_status()`, los controllers vienen agrupados por una key MQTT que **suele coincidir** con `_config_name` pero no es garantizado.
- Bug existente en `routines/pmm_mister_supervisor.py:71`: `cfg.get("id") or cfg.get("controller_id", "")` — ninguno de los dos campos viene poblado por defecto. La key real es `_config_name`.

### Decisión

**Formato canónico**: `controller_id = "{bot_name}::{_config_name}"`

**Justificación**:
- Único cross-bot (incluye bot_name).
- Mapeable a `(bot_name, config_name)` por simple split.
- Estable mientras el filename no cambie.
- Compatible con el formato existente de Condor (los configs hoy se llaman `001_pmm_binance_BTC-USDT.yml` etc.).

**Helper canónico**:

```python
# condor/agent_framework/identity.py

from dataclasses import dataclass
from typing import Any

@dataclass(frozen=True)
class ControllerIdentity:
    """Canonical identity of a controller within the framework."""
    bot_name: str
    config_name: str       # filename del YAML sin extensión
    connector_name: str    # del config
    trading_pair: str      # del config
    controller_name: str   # ej: "pmm_mister"
    
    @property
    def id(self) -> str:
        """Canonical controller_id: bot_name::config_name"""
        return f"{self.bot_name}::{self.config_name}"
    
    @classmethod
    def parse(cls, controller_id: str) -> tuple[str, str]:
        """Returns (bot_name, config_name) from canonical id."""
        if "::" not in controller_id:
            raise ValueError(f"Invalid controller_id format: {controller_id}")
        bot, cfg = controller_id.split("::", 1)
        return bot, cfg


async def resolve_controller(client, controller_id: str) -> ControllerIdentity | None:
    """Look up full identity from a controller_id. Returns None if not found."""
    bot_name, config_name = ControllerIdentity.parse(controller_id)
    
    # 1. Verify bot is active
    bots_status = await client.bot_orchestration.get_active_bots_status()
    if bot_name not in bots_status.get("data", {}):
        return None
    
    # 2. Fetch configs and find by _config_name
    configs = await client.controllers.get_bot_controller_configs(bot_name)
    cfg = next(
        (c for c in configs if c.get("_config_name") == config_name),
        None
    )
    if cfg is None:
        return None
    
    return ControllerIdentity(
        bot_name=bot_name,
        config_name=config_name,
        connector_name=cfg.get("connector_name", ""),
        trading_pair=cfg.get("trading_pair", ""),
        controller_name=cfg.get("controller_name", ""),
    )


async def list_active_controllers(
    client,
    filter_controller_name: str | None = None,
) -> list[ControllerIdentity]:
    """List all active controllers across all bots, optionally filtered."""
    out = []
    bots_status = await client.bot_orchestration.get_active_bots_status()
    for bot_name in bots_status.get("data", {}).keys():
        configs = await client.controllers.get_bot_controller_configs(bot_name)
        for cfg in configs:
            cname = cfg.get("controller_name", "")
            if filter_controller_name and cname != filter_controller_name:
                continue
            out.append(ControllerIdentity(
                bot_name=bot_name,
                config_name=cfg.get("_config_name", ""),
                connector_name=cfg.get("connector_name", ""),
                trading_pair=cfg.get("trading_pair", ""),
                controller_name=cname,
            ))
    return out
```

## F2 — `compute_match_score` + `read_controller_performance_window` (🔴)

### Investigación

Verificado: la API de Hummingbot **no guarda historial server-side** de performance per-controller. Solo snapshot actual via MQTT. Implicancia: el framework **debe persistir sus propios snapshots** en `state/controller_performance/` (esto ya está en spec — confirmado).

### Definiciones concretas

**`read_controller_performance_window`**:

```python
def read_controller_performance_window(
    agent_dir: Path,
    canonical_id: str,
    from_ts: datetime,
    to_ts: datetime,
) -> WindowSnapshot | None:
    """
    Read persisted snapshots from state/controller_performance/<id>.jsonl
    that fall within [from_ts, to_ts].
    
    Returns the deltas between the closest snapshot to from_ts and the
    closest to to_ts (or None if no snapshots in range).
    """
    path = agent_dir / "state" / "controller_performance" / f"{sanitize_filename(canonical_id)}.jsonl"
    if not path.exists():
        return None
    
    samples = []
    with open(path) as f:
        for line in f:
            try:
                entry = json.loads(line)
                ts = datetime.fromisoformat(entry["ts"].replace("Z", "+00:00"))
                if from_ts <= ts <= to_ts:
                    samples.append((ts, entry))
            except Exception:
                continue
    
    if len(samples) < 2:
        return None
    
    samples.sort(key=lambda x: x[0])
    first_ts, first = samples[0]
    last_ts, last = samples[-1]
    
    return WindowSnapshot(
        from_ts=first_ts,
        to_ts=last_ts,
        net_pnl_start=first["r_pnl"] + first["u_pnl"],
        net_pnl_end=last["r_pnl"] + last["u_pnl"],
        volume_start=first["vol"],
        volume_end=last["vol"],
        positions_start=first["pos"],
        positions_end=last["pos"],
        samples_count=len(samples),
    )
```

**Sanitización de filename**: `bot::config_name` → reemplazar `::` por `__` para path-safety: `bot__config_name.jsonl`.

**`compute_match_score`**:

Esta es la fórmula que mide qué tanto el outcome real matchea el outcome predicho por el backtest. Es el corazón del feedback loop.

```python
def compute_match_score(
    actual_pnl_delta: float,
    expected_pnl_delta: float,
    actual_volume_delta: float,
    expected_volume_delta: float,
) -> float:
    """
    Compute how well actual outcome matched the backtest prediction.
    
    Returns score in [0.0, 1.0]:
      - 1.0 = perfect match
      - 0.5 = mediocre (one dimension off, the other ok)
      - 0.0 = total mismatch (both wrong sign, or expected positive got negative big)
    
    Treats PnL and volume symmetrically with weighted average:
      - PnL match: 0.6 weight (más importante porque es lo que importa al usuario)
      - Volume match: 0.4 weight
    """
    pnl_match = _dimension_match(actual_pnl_delta, expected_pnl_delta)
    vol_match = _dimension_match(actual_volume_delta, expected_volume_delta)
    return 0.6 * pnl_match + 0.4 * vol_match


def _dimension_match(actual: float, expected: float) -> float:
    """
    Single-dimension match score in [0.0, 1.0].
    
    Logic:
      - If both close to zero (|expected| < eps and |actual| < eps): 1.0 (no signal either way)
      - If sign mismatch: 0.0 (peor caso, predicción totalmente errada)
      - If sign match: 1.0 - normalized_error, with floor at 0.0
    """
    eps = 1e-6
    if abs(expected) < eps and abs(actual) < eps:
        return 1.0
    if abs(expected) < eps:
        # Predicción 0, actual no — penalizar pero no a 0 si actual también es chico
        return max(0.0, 1.0 - min(abs(actual) / max(abs(actual), eps), 1.0))
    
    # Sign check
    if (actual > 0) != (expected > 0):
        # Sign mismatch (incluye actual=0 vs expected≠0)
        return 0.0
    
    # Same sign — compute relative error
    rel_error = abs(actual - expected) / max(abs(expected), eps)
    return max(0.0, 1.0 - min(rel_error, 1.0))
```

**Buckets de calidad** (mantenidos de MEMORY_SPEC):
- `match_score > 0.7` → `good`
- `0.4 ≤ match_score ≤ 0.7` → `mediocre`
- `match_score < 0.4` → `bad`

**Justificación de los pesos 0.6/0.4**: el usuario priorizó "volumen sobre PnL" en la fórmula de score del backtest, **pero en el match queremos al revés** — saber si el PnL real coincide con el predicho importa más para confianza en el sistema. Sin embargo, ambos pesan razonablemente para no concentrar todo el juicio en una dimensión que puede ser ruidosa.

**Pendiente futuro**: ajustar pesos con datos reales (Fase F2).

## F3 — Política de cold-start (🔴)

### Problema

`controller_performance` requiere ≥4h de historia para `pnl_velocity_4h`. Pero al arrancar el agente por primera vez no hay datos. Si bloqueamos pasivamente, el agente no hace nada las primeras 4h. Si actuamos sin datos, podemos generar propuestas mal informadas.

Verificado: **no hay precedente** en agentes existentes de Condor.

### Decisión: ventana adaptativa con threshold mínimo

**Comportamiento**:

1. **Tick 1 (cero historia)**: el agente registra el snapshot pero no propone nada. `audit_log` recibe entrada con `action=no_action, reason=cold_start`.

2. **Hasta 30 min de historia**: idem (no proponer, solo observar).

3. **30 min – 4h**: el agente puede proponer **pero usando ventana adaptativa**. En vez de `pnl_velocity_4h`, usa la ventana disponible más larga (ej: si hay 1h de historia, usa `pnl_velocity_1h_effective`). El threshold `suboptimal_now` se evalúa con esa ventana, anotando explícitamente.

4. **≥4h de historia**: comportamiento normal.

### Implementación

```python
def get_effective_velocity_window(history_path: Path) -> tuple[float, str]:
    """
    Return (window_hours, status) based on available history.
    
    status ∈ {"cold_start", "adaptive", "normal"}
    """
    samples = read_jsonl_all(history_path)
    if len(samples) < 3:
        return 0.0, "cold_start"
    
    oldest_ts = parse_ts(samples[0]["ts"])
    age_hours = (now() - oldest_ts).total_seconds() / 3600
    
    if age_hours < 0.5:
        return 0.0, "cold_start"
    elif age_hours < 4.0:
        return age_hours, "adaptive"
    else:
        return 4.0, "normal"


def is_suboptimal(perf, regime):
    window_h, status = get_effective_velocity_window(...)
    
    if status == "cold_start":
        return False  # No data, no decision
    
    pnl_velocity = perf.windows[f"last_{int(window_h)}h"].pnl_velocity
    
    return (
        pnl_velocity <= 0
        and perf.windows["last_1h"].volume_velocity < 0.5 * perf.windows["last_24h"].volume_velocity
        # ... (el resto igual, pero las ventanas se adaptan)
        and perf.diagnostic.suboptimal_minutes >= 30
        and regime.summary.favorability != "optimal"
    )
```

## F5 — Fuente de truth única para whitelist/blacklist (🟡)

### Decisión

**`invariants.yaml` es la fuente de truth canónica**. `_controller_field_metadata.py` (en MCP server) **deriva en runtime** de invariants.yaml.

### Justificación

- `invariants.yaml` es config humana editable.
- `_controller_field_metadata.py` es código ejecutable.
- Ambos referencian las mismas listas → si ponemos invariants como source, no hay drift.

### Implementación

```python
# mcp_servers/hummingbot_api/tools/_controller_field_metadata.py

        "updatable_fields": set(inv["allowed_fields"]),
```

## F7 — Outcome loop cross-archivo (🟡)

### Problema

Patches aplicados al final de un mes (ej: 2026-04-30 23:50) tienen su `outcome_30min` que cae en el mes siguiente (2026-05-01). El outcome loop solo lee el archivo del mes corriente → outcome se pierde.

### Solución

```python
def find_pending_outcomes(agent_dir: Path, now: datetime) -> list[dict]:
    """Scan audit_log of current month + previous month for pending outcomes."""
    state = agent_dir / "state"
    
    files_to_scan = [state / "audit_log.jsonl"]  # mes corriente
    
    # Si estamos en los primeros días del mes, también scaneamos el archivo del mes anterior
    if now.day <= 7:
        prev_month = (now.replace(day=1) - timedelta(days=1)).strftime("%Y-%m")
        prev_file = state / f"audit_log_{prev_month}.jsonl"
        if prev_file.exists():
            files_to_scan.append(prev_file)
    
    pending = []
    for path in files_to_scan:
        for entry in read_jsonl_all(path):
            if entry.get("applied") and entry.get("outcome_30min") is None:
                applied_at = parse_ts(entry["applied_at"])
                if (now - applied_at) >= timedelta(minutes=30):
                    pending.append((path, entry))
    
    return pending


def update_audit_outcome(patch_id: str, outcome: dict, agent_dir: Path):
    """Find audit entry across current + previous month files and update."""
    state = agent_dir / "state"
    
    for path in [state / "audit_log.jsonl", *previous_month_files(state)]:
        if not path.exists():
            continue
        entries = read_jsonl_all(path)
        for entry in entries:
            if entry.get("patch_id") == patch_id:
                entry["outcome_30min"] = outcome
                atomic_rewrite_jsonl(path, entries)
                return True
    return False
```
